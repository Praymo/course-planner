# 做课表时遇到的几个小问题

### 换班失败，旧班不能跟着消失

换同一课程的班次不是「先删再加」。先生成一个去掉旧班、放入新班的候选方案，检查冲突和硬限制，通过后才保存。检查脚本覆盖了失败后保留原选择的情况。

### 偏好不能冒充硬约束

早课和周六允许用户选择软提醒或硬限制。真正的时间重叠直接拒绝。这样既不替用户决定作息，也不会把不可执行的课表包装成可行方案。

### 一张周课表会隐藏日期问题

每周同一时段的两门课，可能只在不同周次开课。反过来，TBA 也不代表没有冲突。当前页面展示这些信息，但日期区间模型还不完整；这应当是后续规则层的工作。

### 课程介绍和当期规则的有效期不同

历史课程介绍可以帮助理解内容，但不能证明当期考核、时间和容量。详情保留来源日期和 SIS 入口，把还需要确认的事情写明。

### 先让它容易打开

单个 HTML 和本地存储适合一个人快速试排。不需要服务端，也没有账号恢复、跨设备同步和多人共享。若要支持这些场景，再拆数据层和状态持久化，而不是现在先增加部署成本。
